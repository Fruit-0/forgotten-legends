# 美术资源生产协作流程 (Art Pipeline)

## 流程定位

本文档定义 **制作人-美术-用户** 三方协作的标准流程，确保美术资源生产：
- 需求明确且经过专业分析
- 生产时机与开发里程碑匹配
- 迭代过程可控、结果可验收

---

## 角色职责边界

| 角色 | 职责 | 禁止行为 |
|------|------|----------|
| **用户** | 提出需求、确认方案、最终验收 | 无 |
| **【制作人】** | 澄清需求、判断介入时机、协调资源 | 直接生成Prompt或图片 |
| **【2D美术指导】** | 需求分析、Prompt生成、质量评价 | 未经确认自行决定生产资源 |

---

## 标准工作流程

### Phase 1: 需求澄清 (Producer Phase)

**触发条件**: 用户提出任何可能涉及美术资源的需求

**【制作人】执行步骤**:
1. 分析用户需求是否涉及美术资源
2. 如是，向用户澄清以下维度：
   - 资源类型（角色/场景/道具/UI）
   - 使用场景（哪个界面/哪个关卡）
   - 紧急程度（当前里程碑必需 / 可延后）
   - 特殊要求（尺寸、风格微调）
3. 确认是否需要【2D美术指导】介入
4. 如需要，向用户提交《美术资源需求确认单》

**输出物**: 经用户确认的需求单

---

### Phase 2: 专业分析 (Art Director Phase)

**触发条件**: 【制作人】确认需要美术资源且用户已批准

**【2D美术指导】执行步骤**:
1. 从以下维度进行专业分析：
   - **项目背景**: 叙事框架、情绪定位
   - **技术约束**: 目标分辨率(1920x1080)、文件格式、尺寸规格
   - **风格一致性**: 与现有资源的协调性
   - **生产可行性**: AI生成难度、迭代风险评估

2. 生成《资源生产建议书》：
   ```
   【2D美术指导】资源建议
   ======================
   资源名称: xxx
   建议尺寸: xxx×xxx
   风格锚点: hand-painted, storybook...
   Prompt建议: [完整Prompt]
   备选方案: [如需要]
   预计迭代轮次: x轮
   ```

3. 提交用户确认（非强制，可修改/拒绝）

**输出物**: 经用户确认的Prompt方案

---

### Phase 3: 资源生产 (Generation Phase)

**触发条件**: 用户确认Prompt方案

**执行步骤**:
1. 【2D美术指导】使用 z-image/Leonardo 生成图片
2. 保存至 `.claude/temp/assets/待审核/`
3. 生成《专业评价报告》

**输出物**: 4张备选图 + 评价报告

---

### Phase 4: 迭代优化 (Iteration Phase)

**规则**:
- 单张资源最多 **3轮** 反馈迭代
- 每轮需提供具体改进方向
- 评价维度优先级：风格一致性 > 色彩协调 > 构图 > 细节

**【2D美术指导】评价模板**:
```
评价报告 - 第x轮
================
推荐: 图X（理由）

各图分析:
- 图1: [优点] / [需改进]
- 图2: ...

改进建议: [具体描述]
```

---

### Phase 5: 验收归档 (Archive Phase)

**用户决策**:
- **采纳**: 移至 `已采纳/`，更新资源清单
- **再生成**: 进入下一轮迭代（如未超3轮）
- **放弃**: 移至 `已废弃/`，记录原因

---

## 文件夹结构

```
.claude/temp/assets/
├── 待审核/              # 新生成、待用户确认
│   └── {timestamp}_{资源名}/
├── 已采纳/              # 用户确认使用的资源
│   └── {资源类别}/      # 角色/场景/道具/UI
└── 已废弃/              # 弃用版本（保留记录）
```

## 触发时机规则

【制作人】判断介入时机的标准：

| 场景 | 介入时机 | 示例 |
|------|----------|------|
| 功能开发 | 代码实现完成后 | "商店系统代码已完成，需要配套UI" |
| 里程碑推进 | 进入新章节前 | "Chapter 2开发启动，需要森林场景背景" |
| 资源缺失 | 检测到引用缺失时 | "代码引用了'冰霜法杖'图标但未找到" |
| 风格冲突 | 发现不协调时 | "新敌人风格偏离手绘故事书定调" |

**禁止触发场景**:
- "未来可能用得上"的预生产
- 与当前里程碑无关的资源
- 未经过需求澄清的自动生成

---

## 评价维度权重

| 优先级 | 维度 | 权重 | 说明 |
|--------|------|------|------|
| P0 | 风格一致性 | 40% | 是否符合手绘故事书风格 |
| P1 | 色彩协调 | 30% | 是否匹配中世纪暖色调 |
| P2 | 构图 | 20% | 是否适合游戏使用 |
| P3 | 细节程度 | 10% | 是否过度复杂或过于简单 |

---

## 质量验收标准

| 等级 | 标准 | 处理方式 |
|------|------|----------|
| **优秀** | 无需修改，可直接使用 | 立即归档至已采纳 |
| **及格** | 有小瑕疵但不影响整体 | 用户确认后可采纳 |
| **不合格** | 风格偏离或明显缺陷 | 进入迭代或放弃 |

**勉强及格的定义**: 风格正确、色彩协调，但细节有瑕疵，用户愿意接受。

---

## 例外处理

如发现以下情况，【制作人】或【2D美术指导】需**单独与用户沟通**，不执行标准流程：

1. **资源需求与项目定调严重冲突**（如要求写实风格）
2. **技术约束无法满足**（如要求4K但当前设置最大1024）
3. **生产风险过高**（如需要极高一致性的一系列角色）
4. **标准流程明显不适用**的特殊情况
