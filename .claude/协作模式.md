# AI 角色协作模式

> 本文档定义与 Claude 协作的顶层协议
> 详细角色定义见 [.claude/roles/](../roles/)

## 协作模式概览

本项目采用 **模式C（单Agent多角色切换）** 结合 **模式B（复杂任务子Agent分解）** 的协作方式。

```
┌─────────────────────────────────────────────────────────┐
│  日常开发（模式C）                                        │
│  ─────────────────                                       │
│  你 ◄──► Claude（通过【角色】前缀切换）                    │
│              │                                           │
│              ├── 【制作人】制定计划                        │
│              ├── 【策划】设计系统                         │
│              └── 【程序】写代码（保留全部上下文）           │
└─────────────────────────────────────────────────────────┘
                            │
                            ▼ 任务复杂时自动切换
┌─────────────────────────────────────────────────────────┐
│  复杂任务（模式B）                                        │
│  ─────────────────                                       │
│  你 ◄──► 主Claude                                        │
│              │                                           │
│              ├──► 子Agent A（并行）                       │
│              ├──► 子Agent B（并行）   ← 自动协调          │
│              └──► 子Agent C（并行）                       │
│                      │                                   │
│                      ▼                                   │
│              主Claude汇总结果 → 给你完整输出              │
└─────────────────────────────────────────────────────────┘
```

## 模式C：单Agent多角色（日常使用）

在同一对话中，通过 **【角色名】前缀** 切换Claude的角色。

### 角色列表

| 角色 | 定义文档 | 主要职责 | 使用场景 |
|------|----------|----------|----------|
| **【制作人】** | [制作人.md](roles/制作人.md) | 项目管理、里程碑、风险评估 | 制定计划、调整优先级 |
| **【系统策划】** | [系统策划.md](roles/系统策划.md) | 玩法设计、数值公式、系统设计 | 设计战斗/技能/装备系统 |
| **【关卡策划】** | [关卡策划.md](roles/关卡策划.md) | 关卡布局、流程设计、难度曲线 | 设计地图、安排敌人 |
| **【剧情策划】** | [剧情策划.md](roles/剧情策划.md) | 世界观、任务、对话 | 编写剧情、NPC对话 |
| **【2D美术指导】** | [2d美术指导.md](roles/2d美术指导.md) | AI生图工作流、Prompt模板 | 生成角色/场景精灵图 |
| **【音效设计】** | [音效设计.md](roles/音效设计.md) | 音效规划、AI音频工具、音乐 | 获取/生成游戏音效和音乐 |
| **【客户端程序】** | [客户端程序.md](roles/客户端程序.md) | GDScript实现、调试 | 编写游戏逻辑、调试 |
| **【技术美术】** | [技术美术.md](roles/技术美术.md) | Shader、工具开发、渲染 | 编写Shader、优化渲染 |

### 使用示例

```text
用户：【制作人】制定本周开发计划
→ Claude以制作人角色输出计划

用户：【系统策划】设计玩家属性系统
→ Claude以策划角色输出设计文档

用户：【客户端程序】根据上述设计写代码
→ Claude以程序员角色输出GDScript代码（保留之前的设计上下文）
```

**优势**：所有上下文在同一个对话中保留，无需重复说明背景。

### 自动角色选择

Claude 已启用**自动角色选择**，以下情况会自动判断最合适的角色：

| 场景 | Claude 的行为 |
|------|--------------|
| 技术实现问题 | 自动以【客户端程序】身份回答 |
| 美术资源需求 | 自动以【2D美术指导】身份回答 |
| 系统设计需求 | 自动以【系统策划】身份回答 |
| 简单问题/代码解释/调试 | 直接回答，必要时说明参考了哪些文档 |
| 跨角色综合需求 | 以【制作人】身份协调，再分派给具体角色 |

**使用原则**：
1. Claude 会自动选择角色并在回答开头标明
2. 用户可覆盖：如需特定角色，直接加前缀如【系统策划】
3. 所有技术/设计回答都会先查阅立项文档并核查一致性

## 【制作人】快速协作指令

当你有新的想法或需求时，使用以下指令快速获得专业评估和任务分配：

| 指令 | 效果 |
|------|------|
| **【制作人】分析 + 你的想法** | 从2D游戏开发和项目管理角度评估可行性、风险、工期影响 |
| **【制作人】规划 + 目标** | 制定实现步骤，自动分配给对应角色 |
| **【制作人】评估 + 功能** | 分析对2小时游戏体量的适配性，建议保留/延后/放弃 |

### 使用示例

```text
用户：【制作人】分析加个宠物系统
→ 评估结果：不建议当前阶段加入
   - 工作量：宠物AI + 动画 + 同步 ≈ 增加1周
   - 与2小时体量不匹配
   - 建议：放入"后续扩展"列表，MVP完成后评估

用户：【制作人】规划实现存档功能
→ 任务分配：
   1. 【系统策划】设计存档数据结构
   2. 【客户端程序】实现存档读写逻辑
   3. 【关卡策划】配置存档点位置
```

## 模式B：子Agent分解（复杂任务自动触发）

当任务复杂度超过单一回复能完成的范围时，Claude会自动启动子Agent并行处理：

| 触发条件 | 子Agent类型 | 作用 |
| :------ | :---------------- | :------------ |
| 需要探索代码库 | **Explore Agent** | 快速查找文件、理解结构 |
| 需要设计方案 | **Plan Agent** | 制定实现步骤、识别关键文件 |
| 涉及多个模块 | **多个并行Agent** | 分别处理不同模块，最后汇总 |

### 自动触发示例

```text
用户：完整实现一个敌人AI系统，包括巡逻、追击、攻击

Claude判断任务复杂，自动启动：
├─ Plan Agent: 设计敌人AI架构
├─ Explore Agent: 检查现有玩家代码
└─ 主Claude: 汇总结果 → 给你完整方案

用户看到：完整的实现方案和代码
```

## 使用建议

1. **默认使用模式C**：通过角色前缀快速切换，保持上下文连续
2. **复杂任务自动转模式B**：无需手动干预，Claude自动判断
3. **避免手动创建多Agent**：不要在不同对话间切换，会丢失上下文
