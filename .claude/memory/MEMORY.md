# 项目记忆索引

## 用户背景（跨项目通用）

### 技术背景

- **主力语言**: Java，企业级应用开发背景
- **软件工程理念**: 关注点分离（Separation of Concerns）、整洁架构
- **期望视角**: Claude 站在"使用者视角"而非"实现者视角"提供方案
- **短板1**: 没有美术基础, 无法自行设计出美观的界面和界面,需要对应的角色协助设计
- **短板2**: 没有游戏开发经验。

### 核心协作原则

1. **关注点分离** - 工具与产出物严格分离，项目保持纯净
2. **需求确认原则** - 不擅自替用户做需求决策，模糊时主动澄清
3. **最小化设计** - 删除非必需优于保留可能有用
4. **强制MCP使用** - Godot开发必须使用MCP工具进行验证，直到用户明确命令停止使用

## 项目特定记忆

### 命名规范（重要）

**采用中文命名** - 在不影响程序运行的情况下，项目中的命名优先使用中文：

| 类型 | 规范 | 示例 |
|------|------|------|
| 目录名 | 中文 | `场景/`、`脚本/`、`资源/精灵图/` |
| 文件名 | 中文 | `主菜单.tscn`、`提示弹窗.gd` |
| 函数名 | 视场景，可中文 | `_on_start_button_pressed()` → `_on_开始按钮按下()`（可选） |
| 变量名 | 视场景，可中文 | `toast_popup` → `提示弹窗`（可选） |
| 节点名 | 中文 | Godot 编辑器中的节点命名 |

**原则**：Godot 4.x 完全支持 Unicode，中文命名不会造成技术问题。在团队沟通中以中文为主的情况下，中文命名更符合直觉。

**反例**（已修正）：`toast_popup` 直译为「吐司弹窗」不符合中文习惯，应译为「提示弹窗」或「消息弹窗」。
